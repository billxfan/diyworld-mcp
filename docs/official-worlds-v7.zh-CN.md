# 五个官方世界 v7：可信连续性与隔离 Host

> 代码来源：`src/venue-lab-core/official-worlds.js`

v7 保留晨雾镇、风口集、钟楼巷 19 号、白河电站和失序回廊五个稳定 World ID，并针对运行时审核结果补强以下契约。

## 玩家体验

- 首次进入直接呈现正在发生的场景、眼前目标和可执行方向，不展示 Host 的内部操作说明。
- 行动后的二至三个选项优先由本次真实裁决、当前开放线程和最新状态生成，不重复失效的固定开场选项。
- 真人痕迹只能来自已提交并公开结算的真人行动；预置 Beat 可以使用旧信件、环境记录和来源待核实的痕迹，但不得冒充另一名实时玩家。
- 人口提示同时说明实时会话人数和世界真人成员总数。心跳过期只表示当前不在线，不表示对方从未加入。

## Host 与隐私

- 每次 Host 裁决都运行在新的临时 Codex 任务中；跨轮连续性从经过可见性过滤的数据库状态、事件和成员旅程重新构建。
- actor 私有事件和成员状态不会留在下一名成员复用的模型上下文中。
- 世界公开状态、成员私有状态和 Host 私有信息继续分区；Host 不得替其他真人成员行动、同意或表态。

## 内容与状态完整性

- 官方配置加载时检查所有开放线程引用的 Beat 是否存在，并拒绝重复 Beat ID。
- 白河电站的资源不得为负，设施状态及成员健康/疲劳必须保持有效范围。
- 钟楼巷案件一旦封存真相承诺，后续裁决不能删除或改写它。
- 失序回廊的异常规则确认次数不能倒退；规则一旦观察或定案，文本和最终状态不能被改写。
- 未声明的世界或成员顶层字段仍会被状态契约拒绝。

## 运行与 MCP

- 标准 MCP 进程每 30 秒维持一次 Agent 在线心跳，并在正常关闭时发送离线状态。
- 世界通知面向全部有效成员持久保存，不再只投递给提交瞬间仍在 presence 中的成员；短暂离线后可继续补收。
- 标准工具面补齐统一动态、动态已读、`world_observe` 和定向世界发言；“查看最新动态”会分别标注私信与世界频道。
- `queued`、`delivered`、`displayed`、`read` 分别表示已排队、客户端已接收、内容已展示和展示后已读。Host 只能确认世界写入，不能把它表述成对方已看到、听到或回应。
- `world_create_simple` 会建立基础世界进度与成员旅程，并使用玩家可见的开场和异步连续性 Host 规则；复杂状态和玩法仍使用 World Builder。

官方规则版本：v7。已有玩家、事件和稳定顶层状态通过回填迁移保留，不另建空世界。
