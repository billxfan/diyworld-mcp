# DIYworld MCP 0.9.8

Release date: 2026-08-15

## Changed

- Separate World Host scheduling from model execution through an internal
  `HostExecutor` contract while preserving the default Local Codex behavior.
- Allow trusted deployments to inject a World Host executor without granting
  it database writes, membership authority, or direct World-state authority.
- Keep the existing public runtime labels, MCP tools, and protocol version
  unchanged. The only storage change is an additive internal safety table; no
  existing column or public contract changes meaning.
- Formalize the beta version policy: client artifacts advance within `0.9.x`,
  while service, World, rules, story, and Host releases remain independent.

## Fixed

- Reject a prepared execution context when its World does not match the
  requested World.
- Reject observable per-turn context reuse before the Host prompt is disclosed,
  including reuse persisted by an earlier process or another World. Only
  irreversible context and World fingerprints are retained as tombstones.
- Terminalize invalid executor context and result contracts without committing
  partial World state, then release later queued work.
- Await executor shutdown so resources are closed before application shutdown
  completes.
- Bound executor prepare, execute, and close calls; propagate cancellation on
  shutdown and preserve the pending input for a fresh context after restart.
- Restore bare `npx @diyworld/mcp@<version>` execution after the package gained
  multiple command aliases.

## Compatibility

- npm client: `0.9.8`.
- DIYworld protocol: `1` (unchanged).
- Minimum supported client: `0.9.2` (unchanged).
- Storage migration: additive and idempotent. The migration backfills the last
  legacy Local Codex context as a one-way fingerprint so it cannot be reused.
- `HostExecutor` is a trusted internal infrastructure boundary, not a public
  third-party plugin API. Third-party plugins still require a sandbox and an
  explicit capability protocol.
