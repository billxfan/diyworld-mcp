# DIYworld MCP 0.9.6

Release date: 2026-08-10

## Changed

- Reframe multiplayer Worlds around persistent Story Loops: every Character
  can continue an independent personal story until explicit causal overlap
  creates a shared Scene.
- Upgrade the World Builder compiler and Director Runtime to v3 with validated
  Loop transitions, suspended-branch resume candidates, effect contracts, and
  server-owned delivery authority.
- Add first-class Scene persistence, participant boundaries, monotonic
  lifecycle transitions, concurrent Scenes, and operational `sync`, `async`,
  and `flexible` policies.
- Make normal `world_visit` and `world_act` responses surface relevant updates
  and actionable collective metadata without requiring a manual “查看消息” or
  `world_observe` step.
- Remove lobby-style presence counts from default entry guidance. Presence is
  transport reachability, not evidence that Characters have met.

## Fixed

- Add a transactional World-delivery outbox with recipient snapshots,
  idempotent retry, database-level semantic deduplication, and honest delivery
  receipts.
- Prevent offline audience drift, duplicate directed notifications, unrelated
  action broadcasts, and silent loss of collective invitations or closures.
- Prevent Hosts from choosing recipients, escalating delivery urgency, editing
  another Character through an unrelated input, or binding an outcome to a
  Scene through untrusted impact hints.
- Keep actor-private inputs, Scene details, collective participant identities,
  response input IDs, and hidden source-event IDs out of unrelated Character
  projections.
- Require replies and directed speech to preserve an explicitly authorized
  Scene, reject cross-Scene and outsider targets, and return `NOT_FOUND` for
  invisible reply targets.
- Require explicit confirmation of the exact current World-rule version after
  rules change; a generic return confirmation no longer accepts new rules.
- Use visibility- and Scene-aware World cursors so an inaccessible Scene event
  cannot advance another Character beyond their visible history.
- Validate Loop and Scene transitions inside the authoritative transaction and
  return applied receipts; invalid transitions roll back judgement and state.

## Verification

- Adversarial multiplayer, privacy, delivery, Loop, Scene, and MCP review passed
  with no remaining P0, P1, or P2 findings.
- Release migration rehearsal and SQLite integrity checks passed.
- npm package dry run and public API canary are required before rollout.
